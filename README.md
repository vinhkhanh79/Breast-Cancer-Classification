# Breast Cancer PCA Classification

**Application of Dimensionality Reduction for Breast Cancer Classification Using Machine Learning**

A Streamlit web application, built with a strict **Frontend / Backend / Machine
Learning** separation (Clean Architecture), that evaluates the Logistic
Regression classifier across PCA configurations on the Breast Cancer
Wisconsin (Diagnostic) dataset.

```
Frontend  →  Backend Service  →  Machine Learning Model  →  Prediction
```

The frontend never imports scikit-learn or loads a `.pkl` file directly — it
only calls functions exposed by `backend/api.py`.

---

## 1. Installation

```bash
cd breast_cancer_pca_project
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Train the models (required once, before running the web app)

```bash
python train.py
```

This will:
1. Load `data/breast_cancer.csv` and run EDA.
2. Split into train/test and fit a `StandardScaler`.
3. Fit PCA for **6 configurations**: No PCA, 10 components, 15 components,
   20 components, 95% explained variance, 99% explained variance.
4. Train the single **Logistic Regression** model for every one of those
   6 configurations.
5. Evaluate every PCA configuration on the held-out test set.
6. Save every artifact to `backend/models/` and every metric to
   `results/metrics/` + `results/tables/comparison_table.csv`.

The web app **never retrains** — it only loads these `.pkl` files.

## 3. Run the web app

```bash
streamlit run frontend/app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## 4. Demo flow

1. **Dashboard** — project overview, dataset size, class distribution.
2. **Prediction** — pick the PCA configuration, either fill in the
   30-feature form (pre-filled with dataset means) or upload a `patient.csv`
   for batch prediction; download `prediction_result.csv`.
3. **Visualization** — Explained Variance, PCA Scatter 2D/3D, ROC Curve,
   Confusion Matrix, Correlation Heatmap, Feature Distribution (all Plotly).
4. **Model Comparison** — full metrics table, bar chart, radar chart across
   the PCA variants for the single Logistic Regression model.
5. **About** — project / student / lecturer / dataset / GitHub info.

### Why this split?

- **`frontend/`** renders widgets and calls `backend/api.py`. It never touches
  scikit-learn, joblib, or `.pkl` files.
- **`backend/api.py`** is the *only* module the frontend imports from the
  backend. It hides every implementation detail behind small, documented
  functions (`get_dashboard_data`, `run_single_prediction`,
  `get_comparison_table`, ...).
- **`backend/services/`** contains the actual ML workflows: training,
  evaluation, prediction.
- **`backend/preprocessing/`** contains all data preparation logic shared by
  `train.py` and the services.
- **`backend/visualization/`** builds every Plotly figure so that neither the
  frontend nor the services duplicate charting code.
- **`backend/models/`** holds the persisted artifacts (`scaler.pkl`,
  `pca_<config>.pkl`, `<model>_<config>.pkl`) produced once by `train.py`.

## Notes

- PCA is always fit on the training split only (no data leakage).
- Uploaded CSV files for batch prediction must contain the same 30 feature
  columns as `data/breast_cancer.csv` (extra columns like `id`/`diagnosis`
  are ignored if present).
- To retrain after changing the dataset, simply re-run `python train.py` —
  the web app will pick up the new artifacts on its next restart.
