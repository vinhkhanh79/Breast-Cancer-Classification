# Breast Cancer PCA Dimensionality Reduction

**Application of Dimensionality Reduction (PCA) on the Breast Cancer Wisconsin (Diagnostic) Dataset**

A Streamlit web application, built with a strict **Frontend / Backend / Machine
Learning** separation (Clean Architecture), that demonstrates PCA-based
dimensionality reduction on the Breast Cancer Wisconsin (Diagnostic) dataset.

```
Frontend  →  Backend Service  →  PCA (Dimensionality Reduction)  →  Reduced Components
```

The frontend never imports scikit-learn or loads a `.pkl` file directly — it
only calls functions exposed by `backend/api.py`.

---

## 1. Installation

```bash
cd breast_cancer_pca_project
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Fit the scaler + PCA (required once, before running the web app)

```bash
python train.py
```

This will:
1. Load `data/breast_cancer.csv` and run EDA.
2. Split into train/test and fit a `StandardScaler`.
3. Fit PCA for **5 configurations**: 10 components, 15 components,
   20 components, 95% explained variance, 99% explained variance
   (plus a full-dimensional PCA used for the Explained Variance chart).
4. Save every artifact to `backend/models/` and a summary of each
   configuration's dimensionality/variance retained to
   `results/tables/pca_summary.csv`.

The web app **never re-fits anything** — it only loads these `.pkl` files.

## 3. Run the web app

```bash
streamlit run frontend/app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## 4. Demo flow

1. **Dashboard** — project overview, dataset size, class distribution.
2. **Prediction** — pick a PCA configuration, either fill in the 30-feature
   form (pre-filled with dataset means) or upload a `patient.csv` for batch
   dimensionality reduction; the app shows the resulting principal
   components (not a diagnosis) and lets you download
   `pca_transform_result.csv`.
3. **Visualization** — Explained Variance, PCA Scatter 2D/3D, Correlation
   Heatmap, Feature Distribution (all Plotly).
4. **About** — project / student / lecturer / dataset / GitHub info.

### Why this split?

- **`frontend/`** renders widgets and calls `backend/api.py`. It never touches
  scikit-learn, joblib, or `.pkl` files.
- **`backend/api.py`** is the *only* module the frontend imports from the
  backend. It hides every implementation detail behind small, documented
  functions (`get_dashboard_data`, `run_single_transform`, ...).
- **`backend/services/`** contains the actual PCA workflow: fitting and
  applying the dimensionality reduction transform.
- **`backend/preprocessing/`** contains all data preparation logic shared by
  `train.py` and the services.
- **`backend/visualization/`** builds every Plotly figure so that neither the
  frontend nor the services duplicate charting code.
- **`backend/models/`** holds the persisted artifacts (`scaler.pkl`,
  `pca_full.pkl`, `pca_<config>.pkl`) produced once by `train.py`.

## Notes

- PCA is always fit on the training split only (no data leakage).
- This application performs **dimensionality reduction only** — there is no
  classification model, so the Prediction page reports the reduced
  principal components, not a diagnosis.
- Uploaded CSV files for batch transform must contain the same 30 feature
  columns as `data/breast_cancer.csv` (extra columns like `id`/`diagnosis`
  are ignored if present).
- To re-fit after changing the dataset, simply re-run `python train.py` —
  the web app will pick up the new artifacts on its next restart.
